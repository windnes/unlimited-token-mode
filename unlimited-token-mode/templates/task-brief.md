## 5. 状态来源

> 哪份文件 / 哪个工具是**唯一权威**。所有"现在是第几步、已经做了什么"的判断都必须回到这里。

- **权威状态文件**：`{{state/run.json}}`
- **事件日志**：`{{state/events.jsonl}}`
- **聚合结果**：`{{state/aggregate.json}}`
- **读取方式（每步开头，第一个强制工具调用）**：`{{cat state/run.json}}`
- **陈旧检测**：`_rev` 与手中值不一致 → 重读，禁止合并

**禁止**：从对话记忆推导状态；"我记得已经跑过了"不是状态。

## 6. 迭代与循环方式

- **谁负责循环**：{{harness / 脚本 / agent}}  ← 默认应为 harness 或脚本
- **驱动脚本**：`{{scripts/loop.sh}}`
- **每轮产物**：`{{state/iter.jsonl}}`（一行一轮）
- **聚合方式**：`{{awk 从 jsonl 重算 → state/aggregate.json}}`
- **停止条件**：{{全部判据通过 / 达到 N 轮 / 连续 3 轮无进展}}
- **断点续跑**：读 `{{iter.jsonl}}` 最后一行的 `i`，从 `i+1` 继续

> 若这里写的是"由 agent 自己在思考里循环 N 次"，视为违反契约 2，重写本节。

## 7. 不设预算声明

> 照抄以下声明，不要改写为"尽量节省"。

```
本任务不设 token / 步数 / 成本上限。
在完成判据全部验证通过之前，不得以"节省""快收工""步数不够"为由跳过核对或推演。
若确实存在硬上限，其确切数字为：{{无 / N 次调用}}。
触顶时的花费优先级：不可逆动作前的核对 > 判据验证 > 状态读取 > 探索 > 措辞。
触顶后的行为：停止，并在报告"未验证项"中逐条说明，不得把未验证项写成已验证。
```

## 8. 禁止事项

- 不得修改 {{不在范围内：例如 SKILL.md、生产配置、他人文件}}
- 不得执行 {{例如：`git push --force`、`DROP TABLE`、删除唯一副本}}
- 不得在未核对的情况下执行任何**不可逆**动作
- 不得用"应该可以""看起来没问题"替代验证输出
- 不得声称完成而不附带**能失败的那条检查**及其真实输出
- 不得把配额告警当作"接下来都不查"的理由
