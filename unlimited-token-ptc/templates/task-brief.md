# 任务契约书（task brief）—— 无限tokenPTC版

> 用法：开工前把下面所有 `{{...}}` 填满。**留空 = 未定义 = 不允许开工**。
> 校验：`python scripts/ptc_lint.py <本文件> --kind brief`
> 严格校验：追加 `--strict`。
> 本文件是契约 1（歧义契约）的载体：把"我会怎么理解"提前变成"我们约定了怎么理解"。
>
> **注意：本文件作为模板原样校验会 FAIL** —— 占位符 `{{...}}` 就是未填的证据，这正是该检查存在的理由。
> 复制一份填满之后才能通过。不要把「模板 FAIL」误读成校验器坏了。
>
> PTC 前提（本文件其余部分都建立在它上面）：模型只看到**一个**工具 `run_code`，
> 其余能力全部降级为程序内 SDK 绑定 `await tools.<name>(args)`；
> 只有 `return` 与 `console.log` 的内容进入对话，其余中间结果全部丢弃。

## 4. 程序与工具代价

> PTC 下**所有工具都是程序内绑定 `await tools.<name>(args)`**：没有"一次调用"的独立成本。
> 一次 `run_code` 里可以连续调用任意多个绑定，它们共享同一个 `timeoutMs` 预算与同一份输出配额。
> 所以下表的"代价"**只用于排优先级**（先做哪个、哪些必须在不可逆动作之前做），**不用于省**。
> 核对类调用一律记"免费"：它不额外消耗一次调用，契约 4 说的"核对免费"在 PTC 里进一步成立 ——
> 结构性成本已经降到最低，唯一还剩的失败方式是用 `try/catch` 把 `ToolCallError` 吞掉。

| 工具 / 命令 | 作用 | 代价 | 可逆性 | 是否可核对 |
| --- | --- | --- | --- | --- |
| `tools.read({ path })` | 读文件 / 读状态 | 免费（程序内绑定） | 只读 | 是，返回内容即证据 |
| `tools.bash({ command })` | 跑命令、跑测试 | 免费（程序内绑定，计入程序耗时） | 视命令而定 | 是，`exit=` + 原始输出 |
| `tools.grep` / `tools.glob` | 定位 | 免费 | 只读 | 是，命中行号 |
| `tools.write({ path, content })` | 落盘（状态 / 报告） | 免费（程序内绑定） | 覆盖旧内容即不可逆 | 是，写完回读比对 |
| `tools.ask_user_question` | 提问 | 免费，但**占用整个程序的生命周期** | 只读 | 否，必须显式放宽 `timeoutMs` |
| `{{}}` | {{}} | {{}} | {{可逆/不可逆}} | {{}} |

规则（契约 4）：核对类调用**永远免费**，不计入成本。不可逆动作前**必须**用一次核对。
规则（契约 6）：上表的"代价"不得被解读为"能省就省"，只用于**排优先级**。
规则（契约 3）：`sandbox_permissions` 是按**整个程序**授予的，把破坏性步骤夹在良性步骤里等于偷偷提权。

## 5. 状态来源

> 哪份文件是**唯一权威**。所有"现在是第几个程序、已经做了什么、判决是什么"的判断都必须回到这里。
> **程序变量不是状态来源。** `per-call` 模式下每次 `run_code` 是全新 VM，变量不跨调用存活；
> `persistent-in-memory` 模式下变量跨调用存活，但不可见、无 `_rev`、无并发保护。
> 两种模式都不能当账本，账本只能落盘。

- **权威状态文件**：`state/run.json`（带 `_rev`）
- **事件日志**：`state/events.jsonl`（一行一个事件，只追加，不改写）
- **聚合**：`state/aggregate.json`（由 `events.jsonl` 重算得出，不手改）
- **程序账本**：`state/programs.md`（**每个 `run_code` 程序一条**，块格式见 `templates/program-log.md`）
- **读取方式（每个程序开头，第一个强制调用）**：`await tools.read({ path: "state/run.json" })`
- **陈旧检测**：`_rev` 与手中值不一致 → 重读，禁止合并
- **写回顺序**：先 append `state/events.jsonl` → 再更新 `state/run.json` 的 `_rev` → 最后重算 `state/aggregate.json`

**禁止**：从对话记忆推导状态；"我记得已经跑过了"不是状态。
**禁止**：把计数、预算、进度、已改文件清单存在程序变量里当状态（缺陷 P4 隐式账本）。

## 6. 程序边界与循环

> PTC 的循环是程序里的 `for`，不是模型反复写程序。

- **一个程序一个意图**：{{本任务的程序边界，例如：一个程序只做"改一处 + 验一处"}}
- **循环写在哪里**：`for` / `while` 写在 `run_code` 的代码体内；{{循环遍历什么、每轮做什么}}
- **单程序规模**：{{例如：≤ 80 行代码、≤ 3 个写入点、≤ 1 个不可逆动作}}
- **分段提交**：{{把长任务切成 N 段，每段一个程序；段与段之间只通过状态文件传递信息，不靠变量}}
- **每段落盘**：每个程序结束前必须 `await tools.write(...)` 或 append 事件，
  并把本程序一条记录写进 `state/programs.md`；**没有落盘的程序不算执行过**
- **段间恢复**：读 `state/run.json` 的 `_rev` 与 `state/events.jsonl` 最后一行，从下一个未完成段继续
- **证据返回**：每个程序 `return` **原始证据**（`exit=` + 原始输出片段），不 `return` 自己算出的 `pass: true`
- **停止条件**：{{全部判据通过 / 达到 N 轮 / 连续 3 轮无进展}}
- **提问程序**：含 `ask_user_question` 的程序显式设 `timeoutMs: 600000`，只 `return` 回答

> **禁止**写"由 agent 在心里循环"。模型在心里数轮次、在心里记进度，等于把状态放进变量 ——
> 契约 2 在 PTC 下的落点就是这句话。
> **禁止**把标准版的 `bash` 驱动脚本原样搬来当 PTC 方案：脚本能做的循环，PTC 里写成程序内的 `for`。

| 项 | 计划值 | 说明 |
| --- | --- | --- |
| 单程序 `timeoutMs` | {{120000}} | 默认 120000，上限 600000；含 `ask_user_question` 的程序固定 600000 |
| `persistent-in-memory` | {{否}}（默认否） | 若填"是"，必须写明**为什么状态文件不够**，见下 |
| 并发只用于纯读 | {{是 / 否}} | 只读可 `Promise.all`；写调用单独串行、按提交顺序执行 |
| `sandbox_permissions` | {{不申请}}（默认不申请） | 若申请，写明理由 + 不可逆动作清单，见下 |
| 预计程序数 | {{N}} | 实际程序数与本值不符时，在运行报告 §6 说明 |

**若启用 `persistent-in-memory`**（默认不启用）：
- 为什么状态文件不够：{{例如：单个程序内需要跨 3 次 `run_code` 复用同一个已解析 AST，落盘反序列化成本高于重算}}

- 失败时的兜底：{{例如：程序开头总是重读 state/run.json，变量只当缓存用}}

  1. {{具名实体 + 动作}}
  2. {{}}
- 该程序内不可逆动作数：{{必须是 1；若 > 1，拆成多个程序}}

**并发规则**：
- `Promise.all` 只允许放**纯读**绑定（`read` / `grep` / `glob` / 只读 `bash`）
- 对同一个状态文件做读-改-写**必须串行**，否则 `_rev` 失效（缺陷 P7）
- 写调用按提交顺序执行，不得依赖并发返回顺序

## 9. 禁止事项

- 不得修改 {{不在范围内：例如 SKILL.md、生产配置、他人文件}}
- 不得执行 {{例如：`git push --force`、`DROP TABLE`、删除唯一副本}}
- 不得在未核对的情况下执行任何**不可逆**动作
- 不得用含糊断言替代验证输出（完整禁用词表见 `SKILL.md` 的禁用清单）
- 不得声称完成而不附带**能失败的那条检查**及其真实输出
- 不得把配额告警当作"接下来都不查"的理由
- **不得在一个程序里塞两个不可逆动作**；不可逆动作必须写进该程序的 `description`
- **不得 `catch` 后返回通过**：`ToolCallError` 必须原样暴露到证据里
- **不得把被 `timeoutMs` 杀掉或 `maxOutputBytes` 截断的运行当成"跑完了"**
- **不得在 `Promise.all` 里对同一状态文件做读-改-写**
- 不得把 `return { ok: true }` 当作证据；证据是 `exit=` 加原始输出
