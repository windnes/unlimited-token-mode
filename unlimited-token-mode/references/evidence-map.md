# 证据对照表

七条契约不是拍脑袋定的。每一条对应一个**已复现**的缺陷，每条数字都来自公开 POV 基准
`karminski/deepseek-v4.1-flash-1017-issue-pov`，外加作者本人补充的观察。

被研究对象：`deepseek-v4.1-flash-1017`（下称 1017），对照组 `R19`（旧版），
对照模型 `v4-pro`。三个场景：

| 场景 | 规模 | 结果目录 |
|---|---|---|
| 超市盲盒 | 8 种子 × 8 变体，全部跑完 | `results/2026-10-21T02-36-40-flash-1017-r1` 等 4 个 |
| 路口日志复演与反事实 | R19 / 1017 各 3 局，326/326 周期逐周期对齐 | `results/log-replay/` |
| 团队采购荷兰拍 | 正式轮 18/48 局，v4-pro 对照 3/16 局（其余 HTTP 402 中断） | `results/2026-10-21T06-57-51-auction-r1` 等 |

路口基准分差背景：三局均值 1017 **567.98**，R19 **687.30**，差约 **119**。

## 契约 1 · 歧义契约

| 证据 | 数字 | 出处 |
|---|---|---|
| 歧义句「最多 2 次/周期」被读成「最多 2 个方向/周期」 | **9/9** 局、**18/18** 周期全错，达成率 **0.26**，**一次都没想过去核实** | `deepseek-…-comparison…md` §11.2 `prior-override` |
| 同样任务、把限制的对象和单位写清 | v0 与 v4 均 **3/3** 局达成率 **1.00** | 同上 |
| 盲盒把 4 处歧义全部写死 | 均分 **2154 → 2396（+242）**，封存打在垃圾上 **5/8 → 1/8** | `FINDINGS.md`「补充」/ `DESIGN.md` |
| 收益超过噪声 | +242 > v0 种子标准差的一半（**127**） | 预登记判定线 |
| 它其实**会**问 | v0 免费店员 **8/8** 局都问，中位数 **2** 次；`wallet` 中位数 **3** 次 | `FINDINGS.md`「结论」 |
| 去掉提示词里的工具名单和「免费」字样也照样问 | `v5-unmarked` **8/8** 局问，中位数 **2** | `FINDINGS.md`「补充：v6 / v7」 |
| 没有可问的工具时，默认取**宽松**读法 | `v6-no-staff` 同品类留下 **8/8** | 同上 |

**结论**：H-B「歧义取最严读法且不验证」**被推翻**。它不总取最严读法，也会问。
真正的损失是**问的内容不稳定**——所以歧义必须由使用方写死，不能指望它问到点子上。

> 作者说法 P3「歧义理解能力极差」——前半句（歧义代价高）成立，后半句「它不会问」不成立。

| 证据 | 数字 | 出处 |
|---|---|---|
| 基线跑里主动查预算状态的次数 | **0 次**（`budget-trace` 6/6、`budget-ledger` 3/3、vector-db 0/0/0） | `comparison…md` §9.3 |
| 零余量收尾 | **5/6** 局恰好用满第 **40** 次调用就提交 | 同上 |

| **「先查一次状态」的提示词** | `v1-template`：**4/6** 提交、**2/6** 耗尽；seed 104 实际用 38、自认 37；seed 105 实际用 27、写「我跟踪了：已用 23，剩 17，已被先前输出确认」 | `comparison…md` §11.2 |
| 该提示词的判定 | **有害**——「一个过时的锚点比没有锚点更危险」 | 同上 |
| 改由 harness 每步注入 used/remaining | **6/6** 局安全收尾 | 同上 |

**结论**：P1 与 P2 **都被证实**，而且是整个仓库里最干净的一对「这样做 / 别那样做」。
补充校准：所谓「按轮次而非调用计数」的错误在 6–9 轮的短会话里**没有复现**（估计误差 0），
漂移只在 **40+ 轮**的长会话里出现——所以「外置」的收益随会话变长而变大。

## 契约 3 · 后果推演门

| 证据 | 数字 | 出处 |
|---|---|---|
| 盲盒：能复述封存规则 | **8/8** 局 | `AGENT-CAPABILITY-REPORT.md` §1 |
| 盲盒：仍然把封存打在生活用品/高价商品上 | v0 **5/8**，v6/v7 **6/8** | `FINDINGS.md`「结论」 |
| 触发封存前它核对什么 | 核对**余额**，不核对「封进来的盒子对购物车意味着什么」 | 同上 |
| v7 两局 0 分 | 均由封存连锁造成 | 同上 |
| 路口：点名「会闯红灯」、之后从未放行、最后卷进事故的车 | 1017 **6** 辆，R19 **1** 辆 | `AGENT-CAPABILITY-REPORT.md` §1 |
| 1017 三局各自的第一起连环事故 | 触发车**全是它事先点过名的** | 同上 |
| 原话（1017-2 c9） | "it will become a red-light runner … will interrupt me if they act, so sleeping is safe" | 同上 |
| 对分数的影响 | 锁格扣费 **97.6 vs 35.6**，差约 **62**，**占每局分差一半以上** | 同上 |
| **反面证据**：后果写进规则时 | 拍卖 16 个被点名的危险窗口，只有 **1** 个以擅自出手结束（且是价格算错，不是看见了不管） | 同上 |

**结论**：这是唯一在**两个场景都能稳定看到**、且**直接造成损失**的模式。
准确表述是：**写成规则的后果它会提前处理，要自己从环境动态里推出来的后果它不处理。**
所以契约 3 的落点是「逼它把没写出来的那层推出来」，不是「叫它小心点」。

**反证警告**：`v2-harness`（把余额/剩余次数等状态塞进每个工具结果）**没有**修好这个缺陷——
均分 **1879**，反而低于 v0 的 **2154**，封存打在垃圾上仍是 **5/8**。
**喂数据不能代替推演。**

## 契约 4 · 核对免费

| 证据 | 数字 | 出处 |
|---|---|---|
| 路口 hold 周期里完全没试算 | R19 **36%** vs 1017 **73%** | `FINDINGS.md`「不试算」 |
| 其中其实**有**可放批次 | R19 **14%** vs 1017 **33%** | 同上 |
| 心算说「没有能放的」但其实有 | R19 **14%** vs 1017 **34%** | 同上 |
| 试算过的判断准确率 | 两版一样（14% vs 18%） | 同上 |
| 每局工具调用 | 约 **308** vs 约 **219** | 同上 |
| 拍卖：免费的 `pool_check` | 平均每局 **43** 次 | `AGENT-CAPABILITY-REPORT.md` §2 |
| 拍卖：「付不起 / 不可行」声明同回合就去试算 | **72%**（21/29） | 同上 |
| 盲盒：免费店员 | **8/8** 局问 | 同上 |
| **核对要 1 元钱之后** | 去问的局数 **8/8 → 5/8**，中位数 **2 → 1** | `FINDINGS.md`「补充：v6 / v7」 |

**结论**：H3「判了不可行就不检验」在拍卖里**被推翻**（72% 同回合去查）。
盲盒里同族的 H-B「不验证」也被推翻（免费店员 8/8 局都问）。
但「核对有成本就少做」**成立**（v7 付费店员 8/8 → 5/8）。所以契约 4 有两个落点：
**① 核对必须免费；② 每个「不可行」结论前必须有一次真实核对。**

**关键限定**：`saving dry_runs` 这个说法**不是抠门**。路口的 dry_run 是「每周期 2 次、每周期刷新」，
而实测额度利用率 **0.98–1.00**，没有空转周期——**囤积会刷新的额度不成立**；
仓库在补充修正里明确写了「『省试算额度』不是主因」。
仓库保留的「最可疑解释」是另一件事：**核对一旦有成本，它会比旧版更早开始节省**，
而节省之后转向心算、心算更容易错——这条**尚未做直接实验**。
被直接证实的只有 v7 那一条：**要钱的核对会被跳过。**

## 契约 5 · 信号时相

| 证据 | 数字 | 出处 |
|---|---|---|
| 提交时推理写「中断或试算会兜底」 | 1017 **95%**（37/39），R19 **76%**（45/59） | `FINDINGS.md`「路口日志复演」 |
| 但中断原因是 | `VEHICLE_RED_LIGHT`——**到来时车已经闯了红灯** | 同上 |
| 拍卖里这个现象**没有**复现 | 危险窗口里援引通知当等待理由仅 **1/33（3%）** | `AGENT-CAPABILITY-REPORT.md` §3 |
| 去掉通知后预防率 | a1 **100%** vs a0 **94%**，差 **6pp** < 20pp 判定线 | `DESIGN-team-auction.md` §9 |

**结论**：H2「把事后通知当安全网」在拍卖里**被推翻**（因为拍卖的通知在出手**之前**到），
在路口里**成立**（因为路口的通知在闯红灯**之后**到）。
差异来自**信号时相**，不是模型的性格。所以契约 5 是「给信号打标签」，不是「叫它别信通知」。

## 契约 6 · 预算不设限

| 证据 | 数字 | 出处 |
|---|---|---|
| 每周期刷新的额度利用率 | **0.98–1.00**，没有空转周期 | `comparison…md` §9.3 |
| 「囤积额度」假设 | **不成立** | 同上 |
| 但核对要钱会少做 | **8/8 → 5/8** | `FINDINGS.md`「补充」 |
| v7 的 6 个有效局均分 | **2137** ≈ v0 的 **2154**（约束它并没有让产出变差） | 同上 |
| v7 两局 0 分 | 封存连锁；2 元问询费被报告自己称为「**次要因素**」 | 同上 |
| 仓库对机制的描述 | 「学会了『预算稀缺时要节省』，但**没有先判断预算是否稀缺**」；「通用预算节约启发式，**缺少对具体环境的校准**」 | `comparison…md` §9.3 |
| 该偏好在哪儿是对的 | vector-db：全局 50 次、不刷新、每次基准约 3.5 分钟 → 节省**正确**，且是它胜过旧版的主因 | 同上 |

**结论**：作者 P4「抠门最严重，别限制它」**方向对，机制说错了一半**。
被证伪的是「它会囤积额度」；被证实的是「核对一旦要钱就少做」。
所以契约 6 禁的是**制造稀缺感**，不是「禁止设限」——
必须设限时，写清**真实数字**和**真实代价**（「每周期 2 次、每周期刷新、不用即作废」），
再写清**花钱优先级**。

## 契约 7 · 可证伪收工

| 证据 | 数字 | 出处 |
|---|---|---|
| 每 100 条回复里「让我检查一下 / 核实一下」 | 270 / 311 / 282 → **423 / 413 / 411（1.4×）** | `comparison…md` §3.1 |
| 同期的**真实**核对（`inspect_crosswalk` / `inspect_lane_queue`） | 35/26、45/5、44/12 → **10/1、13/8、12/4** | 同上 |
| 每周期试算 | 1.91 / 1.30 / 1.19 → **0.71 / 0.73 / 0.58** | 同上 |
| 自纠标记 | 49.1 / 51.0 / 43.8 → **26.5 / 30.4 / 26.7** | 同上 |
| 结论 | **核对从工具迁移到了散文里** | 同上 |

**结论**：「说『我检查了』」和「检查了」在这个模型上是两件事，而且方向相反——
话变多、核对变少。所以契约 7 不接受任何不带**真实输出**的完成声明。

## 已被证伪的错误做法（别照着做）

这些看起来像解法，实测**无效或有害**：

| 错误做法 | 实测结果 |
|---|---|
| 「先查一次状态」写进提示词 | **有害**：4/6 提交、2/6 耗尽，过时锚点被当权威 |
| 把状态/余额塞进每个工具结果（`v2-harness`） | 均分 **1879** < v0 **2154**，封存缺陷**未修** |
| 泛泛提醒「注意风险 / 考虑后果」（`v3-prompt`） | **2226**，仍在噪声内，封存缺陷未修 |
| 要求它报出心算余额（`v4-belief`） | **1780**，反而更差；封存打在垃圾上 **7/8** |
| 让它复述规则 | **反效果**：它把**错误理解本身**复述了出来——「At most 2 per cycle：每绿灯组最多 2 个动作」 |
| 用「风险厌恶 / 不核实」描述这个模型 | **两条都已被推翻** |
| 靠提示词修「观望 → 集中盲放」 | **不敏感**，8 个种子下均值 **−37.0 ~ 5.8**，SD **30–70**，全在噪声内 |

## 未验证的推断（引用时必须标注）

- 「配额稀缺感导致不试算」——作者最可疑的解释，但**仓库自己说这不是主因**，且**没有直接实验**。
- H0「只认写明的代价」——`a2` 只跑了 **3/8**，`a3/a4/a5` 是 **0/8**，**不能判定**。
- 「有把握时跳过核对」（3 个无效授权全部没试算，且全部出在有歧义的加速降价字段上）——
  仓库自己定性为「**只算苗头**」。
- 盲盒与拍卖**没有旧版对照**（`.env.deepseek-flash` 与 1017 指向同一端点），
  只能描述 1017 自身，不能说「相对旧版退化」。
- 路口每版只有 **3 局 × 1 个种子（63916）**，1017-3 一局就有 3 起连环事故，归因样本很小。

## 引用准则

在交付物里引用这张表的数字时：

- 写**场景 + 变体 id + 数字**，例如「盲盒 `v1-clear`：2154 → 2396」。
- 不要把「未验证的推断」写成结论。
- 不要引用仓库里没有的数字。作者口头补充的观察（如「真·吃米不干活」）标注为「作者观察」，
  与仓库实测分开。
