# 提示词编译器

把任意需求编译成「无限token模式提示词」。五步，每步有产物。

**核心原则**：不要写「请小心 / 请高效 / 请注意风险」。要写**可验证的约束**。
实测：泛泛提醒（`v3-prompt`）均分 2226，在噪声内，缺陷一个没修；而把规则写死（`v1-clear`）是 2396。

---

## 第 1 步 · 提取歧义

扫需求文本，标记所有**可多种读法**的片段。命中以下任一即标记：

| 触发词 | 例子 | 两种读法 |
|---|---|---|
| 数量 + 未写对象 | 「最多 2 次」 | 2 次什么？调用？方向？周期？ |
| 「不同 / 相同」 | 「5 件不同的东西」 | 5 个 SKU？还是 5 个品类？ |
| 「默认 / 正常 / 一般」 | 「默认配置」 | 哪个默认？谁的默认？ |
| 「及时 / 尽快 / 适当」 | 「及时处理」 | 几秒？几轮？ |
| 「保留 / 退回」+ 未写时点 | 「可以退货」 | 只能退刚开的？还是以前的？ |
| 「最多 / 至少」+ 未写单位 | 「最多 2 个」 | 个什么？ |
| 阈值未写比较方向 | 「超过 80%」 | >80 还是 >=80？ |
| 未写失败处理 | 「重试」 | 重试几次？失败后停还是跳过？ |

**产物**：歧义清单，每项两栏——`读法 A` / `读法 B`。

> 实测：一句「最多 2 次/周期」让 1017 **9/9 局**读成「每绿灯组最多 2 个动作」，
> **18/18 周期**全错，且**一次都没想过去核实**。不要指望它问。

---

## 第 2 步 · 消歧

每一项三选一：

1. **问** —— 值得问、且问了能改结果。一次问完，≤3 个问题，每个自带推荐答案。
2. **写死** —— 你能决定。直接写进需求，**不要留「合理即可」**。
3. **记为假设** —— 无法问也无法定。写进假设清单，标明「若此假设错，哪些结论失效」。

**禁止**：留空让它「自行判断」。它填空白的方式是**取最严读法**，然后不核实。

**写法对照**：

| 别写 | 改写 |
|---|---|
| 最多 2 次 | 每周期最多调用 2 次 `check_phase`，每周期刷新，未用即作废 |
| 5 件不同的东西 | 5 件不同商品；同品类的两件商品算不同商品 |
| 可以退货 | 结账前可退购物车内任意未封存商品，包括早先购买的 |
| 及时处理 | 每轮开始先处理「再不处理就会升级」的项，其余按 FIFO |
| 高效完成 | （删掉，见第 4 步） |

---

## 第 3 步 · 外置记账

找出需求里所有**需要跨步保持的量**，逐个指定归属：

| 量 | 归属 | 怎么写 |
|---|---|---|
| 循环次数 | **脚本** | 「用 bash 循环 10 次，每轮写一行 JSON，最后聚合」 |
| 预算 / 配额 | **状态文件 + harness 注入** | 「每轮开头读 `state/budget.json`，不凭记忆」 |
| 进度 / 已完成项 | **状态文件** | 「追加写 `state/progress.jsonl`」 |
| 剩余时间 | **harness** | 「由运行时每轮注入当前时间戳」 |
| 重试计数 | **脚本** | 「脚本内计数，失败 3 次后退出码 2」 |

**绝对不要写**：「先查一次状态」「记住当前值」「自己数」「跑 10 次然后统计」。

> 实测：「先查一次状态」让通过率 **6/6 → 4/6**，2/6 局耗尽预算。
> 原话判定：**「一个过时的锚点比没有锚点更危险」**。

---

## 第 4 步 · 删掉稀缺感

逐条删除以下措辞（它们会让它**用减少核对来省钱**，而不是用减少浪费）：

```
尽量节省 · 不要浪费 · 高效一点 · 用最少的工具调用 · 步数有限
token 有限 · 简洁优先 · 别啰嗦 · 只做必要的
```

如果确实有硬限制，**写清真实数字和真实代价**：

```
✅ 每轮最多 2 次 dry_run，每轮刷新，未用即作废；优先用于不可逆决策点。
❌ dry_run 额度有限，请节约使用。
```

差别：前者让它知道**不用就没了**，后者让它以为**用了就亏了**。

> 实测校准：所谓「抠门」在仓库里被拆成两半——
> **囤积会刷新的额度：不成立**（利用率 0.98–1.00，无空转周期）；
> **核对要钱就少做：成立**（问一次 1 元，8/8 → 5/8）。
> 所以这里删的是「制造稀缺感」，不是「禁止设限」。

---

## 第 5 步 · 写收工判据

每条判据必须**可执行、可失败**：

| 别写 | 改写 |
|---|---|
| 确保功能正常 | 运行 `npm test`，退出码 0，且 `Tests: 42 passed` |
| 数据要正确 | 对 3 个样本逐字段比对源文件，输出 diff 为空 |
| 处理完毕 | `state/progress.jsonl` 行数 == 输入行数，且无 `"status":"error"` |
| 性能要好 | `bench.sh` 的 p99 < 200ms，贴出原始输出 |

**判据数量 = 验收项数量**，一条判据对应一条命令 + 一次真实输出。

---

## 编译后的骨架

```markdown
# 任务：<一句话，可量化>

## 完成判据
- [ ] <判据 1> → 验证：`<命令>`，期望：<真实可比对的输出>
- [ ] <判据 2> → 验证：`<命令>`，期望：<...>

## 歧义决议
| 词 | 读法 | 采用 | 理由 |
|---|---|---|---|

## 假设（若错则失效）
- <假设> → 若错，<哪些判据失效>

## 工具与代价
| 工具 | 代价 | 备注 |
|---|---|---|
| `check_x` | 免费、不限次 | 不可逆动作前必用 |

## 状态归属
- 循环：由 `<脚本路径>` 负责，不自行计数
- 账本：`state/budget.json`，每轮重读
- 环境：由运行时注入 `[STATE ...]`，不作为长期权威

## 预算
不设人为上限。（或：<真实数字> + <真实代价> + <花钱优先级>）

## 禁止
- 不得在无核对的情况下断言「不可行 / 没有可选项」
- 不得把事后通知当作事前保护
- 不得在未点名实体的情况下声称「已评估风险」
```

---

## 快速检查

编译完扫一遍：

- [ ] 每个数字都写了对象和单位
- [ ] 每个「可以 / 允许」都写了时点和边界
- [ ] 每个跨步量都有归属（脚本 / 状态文件 / harness）
- [ ] 提示词里没有任何稀缺感措辞
- [ ] 每条完成判据都能失败
- [ ] 没有任何「先查一次状态」
