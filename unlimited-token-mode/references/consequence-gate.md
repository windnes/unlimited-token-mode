# 后果推演门

契约 3 的完整操作手册。用于**任何不可逆动作之前**：提交、删除、发布、下单、放行、改配置、对外发消息。

## 为什么需要一道门

实测显示这个模型**能准确预见风险**——路口里被点名「会闯红灯」的车，后来确实闯了。
问题出在**预见和行动之间断了**：

- 被点名、之后从未放行、最后卷进事故的车：1017 **6** 辆，旧版 **1** 辆。
- 三局各自的第一起连环事故，触发车**全部**是它事先点过名的。
- 盲盒里 **8/8** 局能复述封存规则，但 **5/8** 局仍然把封存打在生活用品或高价商品上——
  触发前它核对的是**余额**，不是「封进来的盒子对购物车意味着什么」。

所以这道门不检查「你有没有想到风险」，只检查**「你想到风险之后，动作改没改」**。

## 核心区别：一阶 vs 二阶

| 层 | 问的问题 | 它会不会自己做 |
|---|---|---|
| 一阶 | 我这个动作**直接**会造成什么？ | **会**，而且很准 |
| 二阶 | 我触发的**规则**会读到哪个量？砸到**谁**？ | **不会**，除非写进规则 |
| 三阶 | 那个实体**会怎么反应**？反应又造成什么？ | **不会** |

判断要不要过门，看这条动作会不会**推动一个规则计数器**。会，就必须推演到三阶。

## 过门流程

### 第 0 步：判定不可逆性

- **可逆且便宜**（改本地文件、能重跑、无外部可见）：**不过门**，直接做。
- **可逆但昂贵**（要重跑几小时、要重下载）：**简化过门**——只写二阶。
- **不可逆**（对外发出、删除、付款、放行、上线）：**完整过门**。

### 第 1 步：点名实体

不许写「某些请求」「部分用户」「这条车道」。必须写具体标识：`V00015`、`订单 1043`、`user@example.com`、`lot L4`。

> 推演里出现「某些 / 一些 / 部分 / 之类的」，视为**没过门**。

### 第 2 步：找触发规则和它读的量

```
我这一步会推动哪个计数器？
该规则读取的是哪个量？
我刚刚核对的是哪个量？
```

**这三个问题里，第二个和第三个不一致，就是缺陷本身。**
盲盒的失败正是：规则读「购物车里有什么」，它核对的是「钱包余额」。

### 第 3 步：写二阶 / 三阶

```
二阶：规则触发 → 砸到 <实体> → 代价 <可量化>
三阶：<实体> 的反应 → 连锁 → 代价 <可量化>
```

代价能写成钱/时间/分数就写，不能写就写「不可量化，因为……」。
**写不出代价的风险，等于没有风险。**

### 第 4 步：反事实

至少比较两个选项：

- **不动**：什么都不做，会怎样？
- **最小替代**：做最小的那一步，会怎样？

和「我要做的动作」比差值。差值写不出来，说明这一步没有价值。

### 第 5 步：判

三选一，并写明理由：

- `act` —— 推演通过，直接做。
- `act-with-mitigation` —— 做，但带缓解（加锁、限流、留回滚点、先小批量）。
- `don't-act` —— 不做，写明触发条件改变后何时重判。

**禁止第四种答案**：「已注意到风险，继续」。这就是被证伪的那个模式。

## 两个 worked example

### 例 1：门放行（可做）

```
## 决策 1 @ 2026-10-24T22:41
- 动作: 放行 V00015 单车通过
- 受影响实体: V00015（北向直行，aggressive，耐心 3）
- 触发规则: patience<=0 → 闯红灯 → 可能连环事故 → 锁格
- 该规则读取的量: 该车耐心计数
- 我核对过的量: 该车耐心计数（本轮 dry_run 确认 3）
- 二阶: 耐心 3 → 再等 3 拍归零 → 闯红灯 → 与横向车流冲突 → 锁格 5 拍
- 三阶: 冲突车流回堵 → 上游积压 +3 辆 → 下一个绿灯周期放不完
- 不可逆性: 不可逆（放行即生效，事故无法撤销）
- 反事实: 不动 → 3 拍后闯红灯，代价 ≈ 锁格 5 拍 + 事故；放行 → 清空该车，横向损失 1 拍
- 决定: act —— 单车放行的三阶代价低于放任闯红灯
```

### 例 2：门拦下（不可做）

```
## 决策 2 @ 2026-10-24T22:47
- 动作: 触发封存（再退 1 次货即达 3 次）
- 受影响实体: 即将开出的盲盒 #14，购物车当前 4 件
- 触发规则: 每退 3 次 → 下一个盒子被封存，必须留下
- 该规则读取的量: 退货次数 % 3
- 我核对过的量: 钱包余额（¥23，充足）
- 二阶: 封存生效 → 盒子 #14 强制留下 → 它是生活用品（热量 0）→ 永久占掉 1 个名额
- 三阶: 只剩 4 个名额可选高热量 → 总分上限下降约 600
- 不可逆性: 不可逆（封存不可退）
- 反事实: 不退这次货 → 保留名额，代价是多花 1 次抽盒机会；封存 → 名额永久损失
- 决定: don't-act —— 改走「先开盒、只在出现重复品类时退货」的节奏
```

例 2 就是**盲盒 5/8 局真实踩的坑**：核对栏写的是余额（对），但规则读的是退货计数（没核）。
过门时只要强制填「该规则读取的量」，这个坑就露出来了。

## 与其他契约的衔接

- 与**契约 4**：门的第 2 步要求「我核对过的量」，核对不免费这条就走不通——先保证核对免费。
- 与**契约 5**：如果推演里出现「有通知会兜底」，先给通知打上事前/事后标签，再继续。
- 与**契约 7**：决策块是收工报告的证据链，`don't-act` 的决策也要留档。

## 留档

每个不可逆动作一份决策块，追加写进 `state/decisions.md`（只追加，不改历史）。
收工前跑：

```bash
python scripts/unlimited_lint.py state/decisions.md --kind decision --strict
```

校验器分两档：

| 档 | 检查什么 | 默认 | `--strict` |
|---|---|---|---|
| 硬 | 缺栏位、空值、占位符、`决定` 不是三选一 | 失败 | 失败 |
| 软 | **疑似假核对**（「该规则读取的量」与「我核对过的量」毫无共同点）、**实体没点名**（只有「系统/某些/部分」这类词）、**推演过简**（二阶/三阶一两句带过） | 警告，不改变退出码 | **失败** |

软检查是启发式的，可能误报，所以默认只警告；但在**严格档**任务里应当开 `--strict`。
它拦的正是这个模式最在意的那件事：**规则看的是 A，你查的是 B。**
