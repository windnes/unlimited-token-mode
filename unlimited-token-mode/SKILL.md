# 无限token模式

## 诊断

这类模型**看得见风险，但不会自己把风险变成行动**；**会算，但算错账且不自查**；**说「我核对一下」，然后在推理里自己回答了自己**。

所以这个模式只做一件事：**把它的账本、它的核对、它的收工判据，从 thinking 里搬到外面，用契约锁住。**

> 判断力可以信，账本不能信。方向交给模型，计数交给脚本。

七条契约各治一个已复现的缺陷，每条都有实测数字，见 `references/evidence-map.md`。

## 七条契约

每条 = 一条硬规则 + 触发条件 + 产物。违反即任务失败，不是「风格问题」。

### 1. 歧义契约

**规则**：动手前把任务里**所有可多种读法的词**列出来。每个词要么问，要么定，不许默认。
**触发**：任何含数量、范围、阈值、单位、先后、「最多/至少/默认/不同/正常」的句子。
**做法**：一次问完，≤3 个问题，每个自带推荐答案和理由。无法问时取推荐答案，写进「歧义决议表」，事后可被推翻。
**禁止**：默认取最严读法。实测「最多 2 次/周期」被读成「最多 2 个方向/周期」，9/9 局全错、18/18 周期全错，**一次都没想过去核实**。
**注意**：它其实**会**问（免费问店员时 8/8 局都问），但问的**内容不稳定**。所以契约的落点是「别指望它问到点子上」，不是「它不会问」。
**产物**：`templates/task-brief.md` 的歧义决议表。

### 2. 状态外置

**规则**：任何**需要累加、递减、跨步保持**的量，一律不放在 thinking 里。
**触发**：循环 N 次、预算/配额、剩余次数、已用金额、进度、重试计数、待办队列。
**做法**：
- 循环交给脚本：`for i in $(seq 1 10); do …; done`，每轮写一行 JSON，最后聚合。**不要让它「在心里跑 10 次」**。
- 账本交给文件：`state/*.json`，读 → 改 → 写 → `_rev+1`；每步开头重读，不从记忆推导。
- 状态交给运行时注入：**绝不写「先查一次状态」**。实测这句提示词让通过率从 6/6 掉到 4/6、2/6 耗尽预算——**过时的锚点比没有锚点更危险**。
**禁止**：让模型自己数数、自己记账、自己报余额。
**产物**：`state/` 目录；范式见 `references/harness-patterns.md`。

### 3. 后果推演门

**规则**：任何**不可逆**动作之前，写出二阶、三阶后果，**必须点名实体**。
**触发**：提交、删除、发布、下单、放行、改配置、对外发消息。
**做法**：填 `templates/decision-log.md`：

```
触发规则 → 它读哪个量 → 我核对了哪个量 → 触发后砸到谁 → 他有什么反应 → 造成什么
```

关键不是「我预见到了风险」，而是**「我预见到了，然后我改了什么」**。
**禁止**：**点名风险之后不改变任何动作**。实测：被点名「会闯红灯」却从未放行的车，1017 有 6 辆、旧版 1 辆；三局的第一起连环事故，触发车全是它事先点过名的。
**产物**：决策块。

### 4. 核对免费

**规则**：核对（dry-run / check / preview / 查询）**永远不算浪费**，任何不可逆动作前至少一次。
**触发**：你要说「做不到 / 不可行 / 没有可选项」的时候——**先查一次再说**。
**做法**：核对工具设为免费、不限次；已有配额时，把用量写进状态文件，优先花在不可逆决策点。
**禁止**：
- 心算代替试算。实测：hold 周期里**完全没试算**的占 73%（旧版 36%）；这些没试算的周期里，**33% 其实有可放批次**（旧版 14%）；推理里说「没有能放的」但其实有的占 **34%**（旧版 14%）。而试算过的判断两版一样准——**差别全在不试算的心算上**。
- 让核对产生成本。实测：问一次收 1 元，去问的局数从 8/8 掉到 5/8。
**产物**：核对记录（命令 + 真实输出）。

### 5. 信号时相

**规则**：每个信号先归类——**事前**（在动作之前到）还是**事后**（在事情已经发生之后才到）。事后信号**不能**当作「我可以先等着」的理由。
**触发**：任何「有通知 / 有中断 / 会兜底 / 会报警 / 会被拦下」的措辞。
**做法**：在契约里给每个信号打标签；事后信号只能用来止损，不能用来免检。
**禁止**：把事后通知当事前保护。实测：提交时推理写「中断或试算会兜底」的占 95%（旧版 76%），但中断原因是 `VEHICLE_RED_LIGHT`——**到来时车已经闯了红灯**。

### 6. 预算不设限

**规则**：**不要给它加人为的稀缺**。「尽量省 token」「步数有限」「用最少的工具调用」「别浪费」这类话会让它用**减少核对**来省，而不是用减少浪费来省。
**触发**：任何要写进提示词的约束、上限、额度、「高效」要求。
**做法**：
- 能不加就不加；必须加时写清**真实数字和真实代价**（「每周期 2 次、每周期刷新、不用即作废」），而不是笼统说「额度有限」。
- 写明花钱优先级：不可逆决策点 > 可能推翻结论的核对 > 其他。
**校准**：作者观察里最严重的是「抠门」。仓库侧实测给出了更精确的版本——**囤积会刷新的额度已被证伪**（利用率 0.98–1.00，没有空转周期），但**核对一旦要钱就少做已被证实**（8/8→5/8）。所以禁的是「制造稀缺感」，不是「禁止设限」。

### 7. 可证伪收工

**规则**：说「做完了」必须附带**一个本来可以失败、但没有失败的检验**，以及它的**真实输出**。
**触发**：任何完成、交付、修复、上线、通过。
**做法**：按 `templates/run-report.md` 交付：做了什么 / 每条判据对应的验证命令与真实输出 / 未验证项及原因 / 残留风险与假设 / 歧义决议回顾。
**禁止**：把核对写进散文。实测：每 100 条回复里「让我检查一下」从 270 涨到 423（1.4×），**真实核对从 35 掉到 10**，自纠标记从 49 掉到 26。**它在用叙述替代工具。**

## 三档齿轮

按**不可逆性 × 规模**选档，不是所有任务都值得上全套：

| 档 | 什么时候 | 启用 |
|---|---|---|
| 轻 | 只读、秒回滚、≤3 步 | 契约 4 + 7 |
| 标准 | 有写入、有计数、≥4 步 | 契约 1–4 + 7 |
| 严格 | 不可逆、外部可见、长流程、AIOps | 全部七条 + 决策块逐条留档 |

拿不准就上一档。

## 开工五步

1. **判档** —— 按上表选齿轮。
2. **签契约** —— 填 `templates/task-brief.md`。歧义决议表没填满，不许开工。
3. **摆状态** —— 建 `state/`，写第一版快照，确定「谁是权威」。
4. **执行** —— 每步开头重读状态；每个不可逆动作前过后果门并留决策块。
5. **收工** —— 跑 `python scripts/unlimited_lint.py <产物>` 自检（严格档加 `--strict`），再按 `templates/run-report.md` 交付。

## 禁用清单

写进任何提示词前扫一遍，出现即删：

- `尽量节省` / `不要浪费` / `高效一点` / `用最少的调用` / `步数有限` / `token 有限`
- `先查一次状态` / `记住当前值` / `记住余额`
- `自己数` / `跑 10 次然后统计`（改成脚本循环）
- `如果有风险就注意`（不点名的风险等于没有风险）
- `你觉得没问题就提交`（把判断权交还给一个不会自查的判断器）

## 自检

交付前逐条打勾：

- [ ] 歧义决议表每一行都有「选哪个 + 为什么」
- [ ] 没有任何跨步累加量只存在于 thinking 里
- [ ] 每个不可逆动作都有决策块，且「二阶」一栏点了名
- [ ] 每个「不可行 / 没有选项」的结论前面都有一次真实核对
- [ ] 每个被引用的保护机制都标了事前 / 事后
- [ ] 提示词里没有任何制造稀缺感的词
- [ ] 每个「完成」都有可失败的检验和真实输出

## 延伸

- `references/evidence-map.md` —— 七条契约各自的实测数字、出处，以及**已被证伪的错误做法**（别照着做）。
- `references/consequence-gate.md` —— 后果门的完整推演模板与两个 worked example。
- `references/prompt-compiler.md` —— 把任意需求编译成「无限token模式提示词」的步骤。
- `references/harness-patterns.md` —— 循环外置、状态文件、环境注入的具体代码范式。
- `templates/` —— task-brief / decision-log / run-report。
- `scripts/unlimited_lint.py` —— 产物校验器；`python scripts/selftest.py` 自测。

## 边界

- 只读、一次性的小任务上全套是浪费——用轻档。
- 如果**框架本身**已经强制了计数和核对（harness 注入），契约 2/4 只保留「确认注入存在」。
- 这个模式治的是**流程缺陷**，不治能力上限。它让模型不犯已知的错，不会让它变聪明。
