# 无限token标准版（unlimited token mode）

> 给「判断力可信、账本不可信」的模型加装外置治理层。
> 治的是流程缺陷，不提高能力上限。

---

## 这个模式治的五件事（都来自 upstream 复现，不是假想）

| # | 缺陷 | 表现 | 本模式的对应机制 |
| --- | --- | --- | --- |
| 1 | 在 thinking 里计数 | 让它「跑 10 次然后统计」会漂移 | 循环交给脚本/harness，每轮落一行 JSON（契约 2） |
| 2 | 提示词要求「先查一次状态」 | 会忘，或把首次快照当权威 | 状态由 `utc-ledger` 每步注入，不从记忆推导（契约 2） |
| 3 | 歧义不澄清 | 按自己的理解做完才发现读错 | 开工前填歧义决议表，`--kind brief` 强制校验（契约 1） |
| 4 | 用叙述替代核对 | 「我确认过了」= 没有核对 | 证据由运行时写进 ledger，模型无法伪造（契约 4 + 7） |
| 5 | 制造预算稀缺 | 「尽量省」会削掉核对而不是削掉浪费 | 禁止稀缺话术，且**核对不计入浪费**（契约 6） |

**第 4 条是本版的核心改动。** v1 把「真实输出」交给模型自己写进 markdown，
lint 只能做字符串交集 —— 于是「抄一遍字段 + 编一句我确认过了」就是合法通过。
v2 把证据的来源从模型移到运行时：

```
模型执行工具  →  utc-ledger 插件旁听 tool/call + tool/result  →  .utc/ledger.jsonl
                                                                      ↓
                                                              lint --ledger 比对
```

模型写不了这个文件，也不知道会被逐字比对。于是：

- **编造核对** = 账本里找不到那次调用 → `LEDGER-NO-CALL`
- **改写输出** = 声称的输出不是真实输出的子串 → `LEDGER-OUTPUT-MISMATCH`
- **假 exit**  = 与账本记录的退出码不符 → `LEDGER-EXIT-MISMATCH`

三条都是客观判定，不是「像不像」的启发式。

## 七条硬规则

### 1. 歧义契约

动手前把任务里所有可多种读法的词列出来——数量、范围、阈值、单位、先后、
「最多/至少/默认/不同/正常/适量」。每个词要么用 `ask_user_question` 一次问完
（≤3 问，每问自带推荐答案和理由），要么显式定死并写进开工简报。
**禁止默认取最严读法，禁止「先按我的理解做，不对再说」。**

### 2. 状态外置

任何需要累加、递减、跨步保持的量——循环次数、预算、剩余额度、已用金额、进度、
重试计数、待办队列——一律不放在 thinking 里。

- 循环用脚本跑：写 `for`/`while` 脚本，每轮落一行 JSON，最后聚合统计。
  **不要「在心里跑 10 次」。**
- 账本写文件：`state/*.json`，读→改→写→`_rev+1`，每步开头重读，不从记忆推导。
- 运行时每步会注入当前调用数与报错数（由 `utc-ledger` 提供），那是权威数字。

**禁止自己数数、自己记账、自己报余额。**

### 3. 后果门

任何不可逆动作之前（提交、删除、发布、下单、放行、改配置、对外发消息），
写二阶三阶后果并点名实体：

```
触发规则 → 读哪个量 → 我核对了哪个量 → 砸到谁 → 他什么反应 → 造成什么
```

**点了名就必须改变动作；只点名风险而不改动作等于没做。**
这条 v1 只写在模板里、代码里从未实现；v2 用 `DEC-CORE-PROHIBITION` 强制：
若二阶/三阶写了具名实体 + 可量化成本，而决定仍是 `act` 且没有缓解措施，直接判失败。

### 4. 核对免费

`--dry-run` / check / preview / 查询永远不算浪费，任何不可逆动作前至少一次。
说「做不到 / 不可行 / 没有可选项」之前，必须先真查一次。
**用心算代替试算一律无效。**

### 5. 信号时相

每个信号先分事前还是事后。事后通知（告警、中断、兜底、会被拦下）
不能当作「可以先等着」的理由，只能用来止损——它到来时事情已经发生了。

### 6. 预算不设限

不要给自己制造稀缺。**禁止**用「尽量省」「步数有限」「用最少的调用」「别浪费」
来减少核对。要省就省重复动作，不省核对。

> 校准记录（来自 upstream）：作者原以为「抠门 = 囤积会刷新的额度」，
> 实测额度利用率 0.98–1.00、没有空转周期，**该假设被证伪**；
> 但「核对一旦要钱就少做」被证实——问一次收 1 元，去问的局数从 8/8 掉到 5/8。
> 所以本条的落点是**禁止制造稀缺感**，不是「禁止设上限」。

### 7. 可证伪收工

说「做完了」必须附带一个**本来可以失败、但没有失败**的检验，以及它的真实输出。
禁止用散文代替工具调用——「让我检查一下」这句话本身不算检查。

## 开工五步

`判档 → 签契约 → 摆状态 → 执行 → 收工`

### 判档

| 档位 | 触发条件 | 守哪几条 |
| --- | --- | --- |
| 轻 | 只读、≤3 步、无可逆动作 | 4、7 |
| 标准 | 有写入、有计数、≥4 步 | 1、2、3、4、7 |
| 严格 | 不可逆、外部可见、长流程、AIOps | 全部七条 + 决策块逐条留档 |

拿不准就上一档。

### 签契约

填 `templates/task-brief.md`，跑：

```bash
python scripts/unlimited_lint.py <brief.md> --kind brief
```

歧义决议表没填满、判据没有可执行命令 → 直接失败，不许开工。

### 摆状态

建 `state/`，写第一版快照，确定「谁是权威」。
启用了 `utc-ledger` 插件的话，`.utc/ledger.jsonl` 会自动出现——那是权威调用记录。

### 执行

每步开头重读状态；每个不可逆动作前过后果门并留决策块：

```bash
python scripts/unlimited_lint.py decisions.md --kind decision --ledger .utc/ledger.jsonl
```

### 收工

填 `templates/run-report.md`，跑：

```bash
python scripts/unlimited_lint.py run-report.md --kind report --ledger .utc/ledger.jsonl
```

## 校验器怎么用

```bash
# 有账本：可证伪档（推荐）
python scripts/unlimited_lint.py run-report.md --kind report --ledger .utc/ledger.jsonl

# 没账本：形态档（更弱，会明确告诉你）
python scripts/unlimited_lint.py run-report.md --kind report

# 严格模式：把非启发式警告也升级为失败
python scripts/unlimited_lint.py run-report.md --kind report --ledger .utc/ledger.jsonl --strict

# JSON 输出，便于接 CI
python scripts/unlimited_lint.py run-report.md --kind report --ledger .utc/ledger.jsonl --json
```

退出码：`0` 通过 / `1` 判定失败 / `2` 输入或用法错误（**不含崩溃**——任何输入都不该让校验器崩）。

四个 kind：

| kind | 对应产物 | 主要拦截 |
| --- | --- | --- |
| `brief` | 任务契约书 | 目标不可度量、判据没命令、歧义未决、循环写进 thinking |
| `decision` | 决策块 | 假核对、决定枚举非法、实体不具名、推演灌水、**核心禁令** |
| `report` | 运行报告 | PASS 没命令/没输出、模糊措辞、未验证项 vs「全部完成」矛盾 |
| `program` | 程序日志（PTC 用） | 只有 exit=0 没输出、可失败性写「无法失败」 |

## 证据分档：不是所有检查都等价

| 档位 | 条件 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| `ledger` | 传了 `--ledger` | 命令真的执行过、输出没被改写、exit 对得上 | —— |
| `shape-only` | 没传账本 | 有命令、有形状化输出、没写纯声明式核对 | **无法证明**这些命令真的跑过 |

CLI 会打印当前档位。**看到 `shape-only` 就不要宣称证据已被验证。**

实测边界：把一条从未执行过的命令写进报告，`shape-only` 档下抓不到，`ledger` 档下抓到。
这是档位的固有上限，不是缺陷隐瞒。

## 禁用清单

这些词出现在你自己的计划或提示词里就删掉：

> 「尽量节省」「不要浪费」「高效一点」「用最少的调用」「步数有限」「token 有限」
> 「先查一次状态」「记住当前值」「记住余额」「自己数」「跑 10 次然后统计」
> 「如果有风险就注意」「你觉得没问题就提交」

报告里禁用：

> 「应该可以」「看起来没问题」「基本完成」「已修复（无输出）」

## 安装

### 只装技能（形态档）

把 `unlimited-token-mode/` 复制到 `~/.dsh/preset-skills/`，或在预设里把
`skill-filesystem` 的 `customSkillDirs` 指向本仓库。

### 装插件（可证伪档，推荐）

在 DSH 预设的 `plugins:` 里加：

```yaml
- id: utc-ledger
  name: 'file:///C:/path/to/unlimited-token-mode/plugins/utc-ledger.mjs'
  config:
    ledgerPath: .utc/ledger.jsonl
    injectState: true
```

路径必须是 `file://` URL，**不能是裸的 Windows 绝对路径**：cordis loader 对不以 `.`
开头的 `name` 直接 `import(name)`，Node 的 ESM loader 只认 `file:`/`data:`/`node:`，
写 `C:\...` 会抛 `ERR_UNSUPPORTED_ESM_URL_SCHEME`，预设变成「加载失败」被 UI 隐藏。

插件做两件事：

1. 旁听每次 `tool/call` 与 `tool/result`，落 `.utc/ledger.jsonl`
2. 每步 pre-step 注入当前状态（已落账调用数、报错数、不可逆动作数）

**第二条是契约 2「状态外置」的运行时实现** —— v1 只在文档里要求模型自己外置，
v2 让运行时替它做。

插件加载后可用 `dsh --patch <patch.yml> --dump-config` 确认它出现在配置里。

**这些测试刻意包含「诚实用例必须通过」的另一半。**

v1 的默认模式就是后者的退化形态。

## 与 v1 的差别（可验证）

同一批 23 个用例（17 个攻击 + 6 个诚实），v1 与 v2 各自的判定：

|  | 正确 | 漏放 | 误杀 | 崩溃 |
| --- | --- | --- | --- | --- |
| v1 | 8 | 14 | 1 | 0 |
| v2 | 23 | 0 | 0 | 0 |

v1 漏放的 14 例：假核对、报告全 PASS 无输出、决定栏「不能 act」被读成 act、
推演灌水、核心禁令未实现、PTC 只有 exit=0、可失败性「无法失败」、
契约书空判据、循环写进 thinking、未验证项 vs 全部完成、模糊措辞、无账本编造。
v1 误杀的 1 例：用真实 `df -h` 输出核对「磁盘水位百分比」被判成假核对。

复现方式：`python scripts/ab_compare.py <v1 的 scripts 目录>`，明细会写成 JSON。

## 边界声明（这些它治不了）

1. **不提高能力上限。** 模型不会因为装了它而更聪明。
2. **`shape-only` 档不能证明执行过。** 没装插件时只能看形态。
3. **启发式永不判失败。** 词元相似度这类信号只作提示——v1 的教训正是
   用不可靠的启发式判失败，把诚实的 `df -h` 核对误杀。
4. **框架已注入状态时，契约 2 只需确认。** 本模式不重复造轮子。
5. **它校验的是留档，不是意图。** 一个铁了心要骗过它的模型仍可以先跑一条
   无关命令、再把它的真实输出填进去。这条它抓不住，也不假装能抓。
